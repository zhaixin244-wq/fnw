## 发现矛盾汇总

### 矛盾 #1：面积预算严重超标 [CRITICAL]

**矛盾编号**：AREA-01 + AREA-02 + MEM-01 + DYN-02
**涉及 REQ**：REQ-005, REQ-003, REQ-012, REQ-029, REQ-030, REQ-031

**矛盾描述**：
- 面积约束 3mm²（含 DFT 2.91mm²）
- 面积预估 3.90mm²，超标 30%
- 主要面积消耗：128-wide SIMD RF（~0.5mm²）、280KB SRAM（~0.8mm²）、RT 单元（~0.3mm²）、Mesh/Async 逻辑（~0.2mm²）

**调和方案**：

| 方案 | 调整内容 | 影响 |
|------|----------|------|
| A | 放宽面积约束至 4.0mm² | 需要顶层重新分配面积预算 |
| B | 裁剪功能：去掉 REQ-034(Geometry Shader) + 降低 RF bank 数（32→16） | 损失旧引擎兼容性，RF 带宽降低 |
| C | 裁剪存储：Shared Memory 128KB→64KB，I-Cache 64KB→32KB | 影响线程块共享数据和指令缓存性能 |
| D | 分阶段实现：v1 去掉 RT+Mesh+Async，v2 再加入 | 延迟竞争力特性上市时间 |

---

### 矛盾 #2：功耗预算偏紧 [HIGH]

**矛盾编号**：POWER-01 + PVT-01 + DYN-02
**涉及 REQ**：REQ-001, REQ-005, REQ-013, REQ-029, REQ-031

**矛盾描述**：
- 功耗约束 500mW
- 5nm @ 2.5GHz 典型动态功耗密度高
- 新增 RT 单元（BVH 遍历）、Async Compute（并行队列）、TC FP8/INT8 增加切换活动
- SS corner + 100°C 结温下功耗可能超预算 20-30%

**调和方案**：

| 方案 | 调整内容 | 影响 |
|------|----------|------|
| A | 放宽功耗约束至 600mW | 需要重新评估散热方案 |
| B | 强制 Clock Gating：未使用功能单元自动关时钟 | 增加控制逻辑复杂度 |
| C | 降低峰值频率：非关键路径降频至 2.0GHz | 影响峰值性能 |
| D | 裁剪 Async Compute，仅支持串行计算队列 | 损失 GPU 利用率提升 |

---

### 矛盾 #3：功耗域 vs CDC 复杂度 [MEDIUM]

**矛盾编号**：POWER-02 + POWER-03 + CDC-01
**涉及 REQ**：REQ-007, REQ-008, REQ-011, REQ-006

**矛盾描述**：
- 4 个独立功耗域（Core + 3 个可关断域）
- 3 个时钟域（core/uncore/axi）
- 集中式 CDC 模块需处理跨功耗域信号隔离
- CDC 异步 FIFO 增加 3-5 cycles 延迟，压缩 10-cycle 管线裕量
- 功耗域关断时 CDC 同步器输出需 Isolation Cell，增加面积

**调和方案**：

| 方案 | 调整内容 | 影响 |
|------|----------|------|
| A | CDC 模块放在 Always-On 域，关断域信号先隔离再进 CDC | 增加 Isolation Cell 面积 |
| B | 减少功耗域至 2 个（Core + 非 Core），简化 CDC | 降低功耗管理灵活性 |
| C | 管线深度增加至 12 cycles 补偿 CDC 延迟 | 影响延迟目标 |

---

### 矛盾 #4：验证复杂度 vs 验证周期 [MEDIUM]

**矛盾编号**：PERF-02 + VER-01 + VER-02
**涉及 REQ**：REQ-024, REQ-025, REQ-029~034

**矛盾描述**：
- 15+ 功能（含 RT/Mesh/Async 等复杂功能）+ 3 接口 + 3 时钟域
- 验证复杂度系数：15 × 3 × 1.5 = 67.5（高复杂度）
- SVA 属性数预估 150-200+，形式验证运行时间数天
- UVM 回归用例预估 2000+，验证周期可能需要 12-16 周

**调和方案**：

| 方案 | 调整内容 | 影响 |
|------|----------|------|
| A | 增加验证团队规模（2→4 人） | 增加人力成本 |
| B | 分阶段验证：先验证核心功能，新增功能单独验证 | 延长整体项目周期 |
| C | 降低覆盖率目标：功能覆盖率 90%→85% | 降低验证质量 |

---

### 矛盾 #5：Geometry Shader vs Mesh Shader 功能重叠 [LOW]

**矛盾编号**：DYN-01
**涉及 REQ**：REQ-034, REQ-030

**矛盾描述**：
- Geometry Shader（传统几何处理）与 Mesh Shader（现代几何处理）功能有语义重叠
- 两者都处理几何图元生成/变换
- Mesh Shader 是 DX12 Ultimate 推荐的 GS 替代方案

**调和方案**：

| 方案 | 调整内容 | 影响 |
|------|----------|------|
| A | 保留两者，GS 作为兼容层（软件模拟或简化硬件） | 面积开销可控 |
| B | 去掉 REQ-034(Geometry Shader)，仅保留 Mesh Shader | 旧引擎需适配 |
| C | GS 用微码模拟，不增加专用硬件 | 性能可能下降 |
