### 轮 2 — REQ-005 面积与功耗

**苏启辰**：

> **锚定**：模块=GPU Shader Core | 定位=GPU 计算单元，SIMT 执行+纹理采样+光栅化+Tensor Core | 硬约束={面积3mm², 功耗500mW, 频率2.5GHz, 5nm} | 阶段=stageB phase1 (REQ-005)

> **说明**：REQ-005（面积与功耗）依赖 REQ-013（PVT 操作条件）。REQ-013 尚未确认，但 stageA 已明确面积/功耗目标，先确认主约束值，PVT 条件后续补齐。

从 stageA 确认的信息中，面积和功耗目标已明确给出。我来做初步可行性分析：

---

**面积可行性分析（5nm 工艺）**

| 子模块 | 预估面积 (mm²) | 计算依据 |
|--------|---------------|----------|
| 执行单元（4 sub-partition x 32 lanes） | ~0.8 | ALU/FPU/SFU 逻辑，5nm 密度约 100MTr/mm² |
| 寄存器文件（Operand Collector, 32 bank） | ~0.4 | 每 bank 128x32b = 4Kb，32 bank 共 128Kb RF |
| Tensor Core（FP8 16x16） | ~0.3 | 脉动阵列 + 累加器 + 格式转换 |
| Warp Scheduler（64 warps） | ~0.15 | PC 表 + 依赖检查 + 调度逻辑 |
| 纹理单元（8 units） | ~0.25 | 采样器 + 插值 + LOD + 纹理缓存 |
| 光栅化引擎 | ~0.2 | 三角形遍历 + 片段生成 + 深度测试 |
| L1 缓存（指令+数据） | ~0.5 | 典型 64KB I$ + 64KB D$ SRAM |
| 控制逻辑/杂项 | ~0.2 | 寄存器接口、中断、调试 |
| **合计** | **~2.8** | |

**面积结论**：预估 ~2.8mm²，低于 3mm² 预算，**裕量约 7%**。面积约束基本满足，但裕量较小，需注意：
- L1 缓存大小直接影响面积，如需更大缓存可能超标
- ECC/Parity 开销（~3-5%）会进一步压缩裕量

---

**功耗可行性分析（5nm, 2.5GHz, TT/0.75V/25C）**

| 子模块 | 动态功耗 (mW) | 计算依据 |
|--------|-------------|----------|
| 执行单元 | ~150 | α=0.15, C≈120pF, V=0.75V, f=2.5GHz |
| 寄存器文件 | ~60 | 高翻转率，32 bank 读写 |
| Tensor Core | ~100 | 脉动阵列密集运算 |
| Warp Scheduler | ~20 | 控制逻辑 |
| 纹理单元 | ~40 | 采样 + 缓存访问 |
| 光栅化 | ~25 | 片段处理 |
| 缓存系统 | ~50 | SRAM 读写 + 标签比较 |
| **动态合计** | **~445** | |
| 静态功耗 | ~55 | 5nm 漏电，~20kTr/mm² 有效 |
| **总计** | **~500** | |

**功耗结论**：预估 ~500mW，**恰好触及预算上限**。这是高风险项：
- SS corner / 高温场景下功耗会超出预算
- 需要激进的 Clock Gating 策略降低实际翻转率
- 建议后续 stageD 详细设计时做功耗优化

---

**风险提示**：
- `[HARD-CONSTRAINT-RISK] 功耗预估 ~500mW 恰好等于预算 500mW，无裕量。建议在 stageD group5-step6 做详细功耗优化设计。`
- 面积裕量仅 7%，L1 缓存和 ECC 开销可能导致超标。

---

请确认：
1. **面积约束 3mm²** — 是否接受？
2. **功耗约束 500mW** — 是否接受？（注：预估已触及上限，建议考虑是否需要留裕量）

### 轮 6 — REQ-008 DFT

**苏启辰**：

> **锚定**：模块=GPU Shader Core | 定位=GPU 计算单元，SIMT 执行+纹理采样+光栅化+Tensor Core | 硬约束={面积3mm², 功耗500mW, 频率2.5GHz, 5nm} | 阶段=stageB phase1 (REQ-008)

REQ-008（DFT）涉及 4 个子项，我逐项分析：

---

**1. 扫描链（Scan Chain）**

5nm / 2.8mm² 面积下，预估寄存器数量约 200K~300K FF。需要多条扫描链以控制测试时间。

| 参数 | 推荐值 | 理由 |
|------|--------|------|
| 扫描链数量 | 64~128 条 | 测试时间 = FF数 / 链数 / 频率，128 条约 1ms |
| 扫描压缩比 | 10:1 ~ 20:1 | 5nm 工艺典型值，减少 ATE 通道需求 |
| 扫描时钟 | 复用 core 时钟域 | 2.5GHz 功能时钟，测试时降频至 100~200MHz |

**与 4 个功耗域的关系**：每个功耗域需独立扫描链分区，关断域的扫描链需隔离。

---

**2. ICG（Integrated Clock Gating）**

REQ-007 已确认 4 个独立功耗域，ICG 是低功耗设计的核心 DFT 元素。

| 功耗域 | ICG 数量（预估） | 使能信号 | Scan Enable |
|--------|-----------------|----------|-------------|
| Core（Always-On） | 8~12 | 各子模块 idle 信号 | scan_en_core |
| Tensor | 3~5 | tensor_power_en | scan_en_tensor |
| Texture | 3~5 | texture_power_en | scan_en_texture |
| Raster | 2~4 | raster_power_en | scan_en_raster |

**关键约束**：所有 ICG 必须带 `scan_en` 端口，测试模式下绕过门控。

---

**3. Boundary Scan（JTAG）**

| 参数 | 推荐值 | 理由 |
|------|--------|------|
| JTAG 支持 | 是 | 板级调试和测试必需 |
| IEEE 1149.1 | 兼容 | 标准边界扫描协议 |
| TAP 控制器 | 独立 | 共享 axi 时钟域 |

**注意**：JTAG 接口信号（TDI/TDO/TCK/TMS/TRST）需要独立于功能路径。

---

**4. MBIST（Memory BIST）**

GPU Shader Core 包含大量 SRAM，MBIST 是必须的。

| 存储器 | 容量（预估） | MBIST 类型 | 说明 |
|--------|-------------|------------|------|
| L1 指令缓存 | 64KB SRAM | 标准 March C+ | 指令缓存 |
| L1 数据缓存 | 64KB SRAM | 标准 March C+ | 数据缓存 |
| 纹理缓存 | 16~32KB SRAM | 标准 March C+ | 纹理采样 |
| 寄存器文件 | 128KB（32 bank） | 标准 March C+ | Operand Collector |
| Tensor Core 累加器 | 4~8KB SRAM | 标准 March C+ | 脉动阵列累加 |
| **合计** | **~280KB** | | |

**MBIST 控制器**：建议 2~3 个 MBIST 控制器，分别覆盖不同功耗域的 SRAM。

---

**DFT 面积开销预估**

| DFT 组件 | 面积开销 (mm²) | 占比 |
|----------|---------------|------|
| 扫描链 + 压缩逻辑 | ~0.05 | ~1.8% |
| ICG（20~30 个） | ~0.02 | ~0.7% |
| JTAG TAP + Boundary Scan | ~0.01 | ~0.4% |
| MBIST 控制器（2~3 个） | ~0.03 | ~1.1% |
| **合计** | **~0.11** | **~4%** |

`[HARD-CONSTRAINT-CHECK] DFT 面积开销 ~0.11mm²，加上之前预估 2.8mm²，合计 ~2.91mm²，仍在 3mm² 预算内，但裕量进一步压缩至 ~3%。`

---

**风险提示**：
- `[HARD-CONSTRAINT-RISK] 面积裕量仅剩 ~3%（含 DFT 开销），任何额外功能添加都可能超标。`
- DFT 与 4 个功耗域的交互较复杂，扫描链分区和 MBIST 隔离需要在 stageD 详细设计。
- 5nm 工艺下 SRAM MBIST 的故障模型可能需要额外的 retention test。

---

请确认：
1. **扫描链方案**：64~128 条扫描链 + 10~20x 压缩 — 是否接受？
2. **ICG 方案**：每个功耗域独立 ICG，均带 scan_en — 是否接受？
3. **Boundary Scan**：IEEE 1149.1 JTAG — 是否接受？
4. **MBIST**：2~3 个控制器覆盖 ~280KB SRAM — 是否接受？

如果有特殊 DFT 要求（如 LBIST、特定故障覆盖率目标、ATE 通道限制），请告知。
