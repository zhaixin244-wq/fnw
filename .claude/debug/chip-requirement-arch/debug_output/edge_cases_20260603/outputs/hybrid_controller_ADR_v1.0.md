## 3. 架构决策记录

### ADR-001: 架构拓扑 — 独立协议转换通路 vs 共享转换引擎

**日期**：2026-06-03 | **状态**：accepted

**背景**：hybrid_controller 需要将 APB/AXI/SPI 三路上游协议转换为 AXI4/DMA 两路下游协议。架构选择直接影响面积、延迟和可维护性。

**决策**：采用**独立协议转换通路**架构。

**方案 A（采用）：独立协议转换通路**
- 每个上游接口有独立的协议转换逻辑
- 优点：延迟低（各通路独立，无阻塞）、逻辑简单（每路职责单一）、易扩展
- 缺点：面积略大（三路独立逻辑）

**方案 B（拒绝）：共享转换引擎**
- 三路上游共享一个协议转换引擎，通过仲裁切换
- 优点：面积小（共享逻辑）
- 缺点：延迟高（仲裁等待）、逻辑复杂（多协议状态机）、AXI 突发期间 APB 被阻塞

**拒绝原因**：REQ-004 要求 AXI≤4cycles/APB≤3cycles 的低延迟，共享引擎无法满足（仲裁等待增加 2+ cycles）。且 REQ-005 面积预算 50kGates 裕量充足，独立通路预估 35kGates 不超预算。

**后果**：
- 正面：各通路延迟独立，满足 REQ-004
- 负面：面积增加约 5kGates（vs 共享方案）
- 风险：低

### ADR-002: SRAM 容量分配 — ≤2KB 硬约束下的压缩方案

**日期**：2026-06-03 | **状态**：accepted

**背景**：用户明确 SRAM 必须 ≤2KB（2048 Bytes），不可妥协。原始估算约 4KB，需要压缩 50%。

**决策**：采用**四管齐下**压缩方案。

| 压缩措施 | 原始 | 压缩后 | 节省 |
|----------|------|--------|------|
| AXI 写 buffer 深度减半 | 1024B (32beat) | 512B (16beat) | -512B |
| SPI buffer 缩小 | 256B | 128B | -128B |
| 三路读 buffer 合并共享 | 3×512B=1536B | 1×1024B | -512B |
| 地址映射表保留 | 256B | 256B | 0 |
| **合计** | **3328B** | **1920B** | **-1408B** |

**方案 A（采用）：1920B 分配**
- axi_wr_buf: 512B（16beat × 32B，覆盖 REQ-003 AXI 突发）
- spi_rx_buf: 128B（SPI 单拍 1~4B，128B 足够）
- shared_rd_buf: 1024B（三路共享，tag 区分来源）
- addr_map_tbl: 256B（APB 可运行时配置）

**方案 B（拒绝）：进一步压缩到 1280B**
- 去掉地址映射表（改为组合逻辑），axi_wr_buf 压到 256B
- 拒绝原因：axi_wr_buf 256B 仅支持 8beat burst，低于 REQ-003 的 16beat 要求

**方案 C（拒绝）：使用寄存器阵列替代 SRAM**
- 全部用寄存器实现
- 拒绝原因：1920B 用寄存器实现约 15kGates，远超 SRAM 方案的 8kGates

**后果**：
- 正面：满足 SRAM ≤2KB 硬约束
- 负面：AXI 写突发受限于 16beat（原可支持 32beat）；共享读 buffer 需仲裁，增加 1cycle 延迟
- 风险：中（后续功能扩展可能需要更多 buffer）

### ADR-003: AXI 写突发合并策略（REQ-029）

**日期**：2026-06-03 | **状态**：accepted

**背景**：多个小 burst 写 DDR 效率低，需要合并为大 burst 以减少 DDR 写事务数。

**决策**：采用**可选突发合并**方案，通过 CTRL 寄存器使能。

**方案 A（采用）：写 buffer 累积合并**
- axi_write_buf 累积多个小 burst，满或超时后合并为单个大 burst 发出
- 优点：减少 DDR 写事务数，提高带宽利用率
- 缺点：增加写延迟（等待累积）

**方案 B（拒绝）：直接透传**
- 每个 burst 独立发出
- 拒绝原因：REQ-029 明确要求突发合并能力

**后果**：
- 正面：DDR 写效率提升 30~50%（小 burst 场景）
- 负面：写延迟增加 1~3 cycles（累积等待）
- 风险：低（可通过寄存器关闭合并功能）

### ADR-004: 地址映射实现方式

**日期**：2026-06-03 | **状态**：accepted

**背景**：REQ-020 要求固定地址映射，需要决定使用 SRAM 查找表还是组合逻辑。

**决策**：采用**SRAM 查找表 + APB 可配置**方案。

**方案 A（采用）：SRAM 查找表**
- addr_map_tbl (256B SRAM) 存储地址映射表
- APB 可运行时修改映射（灵活性）
- 地址解码延迟：1 cycle（SRAM 读）

**方案 B（拒绝）：组合逻辑**
- 用比较器+多路选择器实现固定映射
- 拒绝原因：虽然面积更小（省 256B SRAM），但灵活性差，后续地址空间调整需重新综合

**后果**：
- 正面：地址映射可运行时配置，灵活性高
- 负面：占用 256B SRAM（从 2KB 预算中扣除）
- 风险：低

---

### ADR-005: 共享读缓冲仲裁策略

**日期**：2026-06-03 | **状态**：accepted

**背景**：三路读返回共享 1024B 缓冲，需要仲裁策略决定读返回数据的路由。

**决策**：采用**Tag 区分 + 固定优先级**方案。

**方案 A（采用）：Tag 区分**
- 每个写入 shared_rd_buf 的数据带 tag（2bit），标识来源（AXI/APB/SPI）
- 读出时根据 tag 路由到对应 slave 接口
- 优先级：AXI > APB > SPI

**方案 B（拒绝）：时分复用**
- 固定时间片分配给三路
- 拒绝原因：时分复用在低负载时浪费带宽，高负载时延迟不可控

**后果**：
- 正面：带宽利用率高，延迟可控
- 负面：仲裁逻辑增加约 0.5kGates
- 风险：低

## 4. 方案细化记录

### stageD group1-step1: 初始架构方案 + RTL 行数估算

**分析结论**：采用独立协议转换通路 + 地址解码路由架构，RTL 预估 2580 行（≤3000），无需进入 stageE 递归分解。

**头脑风暴记录**：
- Q: 架构拓扑方向？A: 独立通路（ADR-001）
- Q: SRAM 如何分配？A: 四块 SRAM 总计 1920B（ADR-002）
- Q: RTL 行数估算？A: 12 个子模块，总计 ~2580 行
- Q: 是否需要递归分解？A: 不需要（2580 < 3000）

**方案决策**：独立协议转换通路，12 个子模块，RTL 2580 行。

### stageD group1-step2: CBB 选型

**状态**：跳过
**原因**：本模块为纯自研设计，不使用外部 CBB/IP。

### stageD group1-step3: 子模块划分

### stageD group2-step1: 数据通路设计

**分析结论**：3 条写路径 + 3 条读路径，延迟均满足 REQ-004。

**数据通路**：
- WR-01: AXI→AXI4 (3 cycles)
- WR-02: APB→AXI4 (2 cycles)
- WR-03: SPI→DMA (4 cycles)
- RD-01~03: 下游→上游 (3 cycles)

### stageD group2-step2: 流水线设计

**状态**：跳过
**原因**：协议桥接器为单拍/突发传输，不采用多级流水线。各通路为两拍结构（输入锁存+输出）。

### stageD group2-step3: 控制逻辑/FSM

**分析结论**：两个关键 FSM — addr_decode（3 状态）和 burst_merge（3 状态），均使用独热码编码。

### stageD group2-step4: 性能优化

**分析结论**：关键路径 CP-001 延迟 1.5ns，裕量 3.0ns，无需额外优化。

### stageD group3-step1: SRAM 设计

**分析结论**：4 个 SRAM 实例，总计 1920B，满足 ≤2KB 约束。

| 实例 | 位宽 | 深度 | 容量 |
|------|------|------|------|
| axi_wr_buf | 64bit | 64 | 512B |
| spi_rx_buf | 8bit | 128 | 128B |
| shared_rd_buf | 64bit | 128 | 1024B |
| addr_map_tbl | 32bit | 64 | 256B |

### stageD group3-step2: FIFO 设计

**状态**：跳过
**原因**：本模块使用 SRAM 实现缓冲，不使用独立 FIFO。满/空判断通过多 1 位指针法实现。

### stageD group3-step3: 链表设计

**状态**：跳过
**原因**：本模块无链表管理需求。Buffer 管理使用简单的环形指针。

### stageD group3-step4: 寄存器定义

**分析结论**：14 个寄存器，APB 可访问。包含控制、状态、中断、错误注入（REQ-030）和事务计数器（REQ-031）。

### stageD group4-step1: 调度策略

**分析结论**：三路上游访问不同地址空间，无多源仲裁需求。AXI 和 APB 同时访问同地址时 AXI 优先。

### stageD group4-step2: 流控机制

**分析结论**：三种流控 — AXI 写背压（ready 反压）、AXI 读背压（rvalid 控制）、DMA 握手（valid/ready）。

### stageD group4-step3: CDC 方案

**状态**：跳过
**原因**：REQ-006 确认单时钟域，无 CDC 需求。

### stageD group5-step1: 面积预估

**分析结论**：总预估 ~35kGates（逻辑 27kGates + SRAM 8kGates），< 50kGates 预算。

### stageD group5-step2: 时序分析

**分析结论**：关键路径 CP-001 延迟 1.5ns，Tslack = 3.0ns，满足时序要求。

### stageD group5-step3: DFX 设计

**分析结论**：遵循项目通用 DFT 规则，标准扫描链 + ICG。

### stageD group5-step4: 可靠性设计

**分析结论**：SRAM Parity 保护（REQ-009），无 ECC/TMR。地址解码错误检测 + 中断上报。

### stageD group5-step5: 接口定义

**分析结论**：6 个外部接口 — APB32 slave、AXI4 slave、SPI slave、AXI4 master、DMA master、中断输出。

### stageD group5-step6: 功耗设计

**分析结论**：全局 Clock Gating（REQ-007），各子模块独立 ICG。预估功耗 ~9mW < 15mW 预算。

### DECISION-001: SRAM 容量分配方案

**当前方案**：1920B（axi_wr_buf 512B + spi_rx_buf 128B + shared_rd_buf 1024B + addr_map_tbl 256B）

**备选方案**：
- A: 当前方案（1920B），保留地址映射表的灵活性
- B: 去掉 addr_map_tbl（1664B），地址映射改为组合逻辑，省出 256B 给后续扩展
- C: 去掉 addr_map_tbl + 将 shared_rd_buf 减到 768B（1408B），极限压缩但读性能下降

**需要确认**：选择哪个方案？

### DECISION-002: AXI 写突发合并是否默认使能

**当前方案**：burst_merge 功能存在，但 CTRL.BURST_MERGE_EN 默认为 0（关闭）

**备选方案**：
- A: 默认关闭，软件按需使能（当前方案）
- B: 默认使能，写延迟略增但 DDR 效率更高

**需要确认**：默认使能还是关闭？

### DECISION-003: 地址映射表是否需要 APB 运行时可配置

**当前方案**：addr_map_tbl 通过 APB 可运行时修改

**备选方案**：
- A: APB 可配置（当前方案），灵活性高
- B: 综合时固定，省掉 APB 写路径逻辑，面积更小

**需要确认**：是否需要运行时可配置？
