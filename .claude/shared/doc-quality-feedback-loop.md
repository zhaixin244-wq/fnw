# 文档质量闭环方法论

> 定义文档评分→改进→复评的闭环流程，以及跨文档一致性自动修复建议机制。

---

## 1. 质量闭环流程

### 1.1 闭环阶段

```
初始评分 → 差距分析 → 改进计划 → 执行改进 → 复评验证 → 达标确认
    ↑                                                    │
    └──────────────────── 未达标 ────────────────────────┘
```

### 1.2 阶段定义

| 阶段 | 输入 | 输出 | 执行者 |
|------|------|------|--------|
| **初始评分** | 文档初稿 | 评分报告（维度得分 + 扣分项） | chip-doc-scorer |
| **差距分析** | 评分报告 | 改进项清单（优先级排序） | 对应 Agent |
| **改进计划** | 改进项清单 | 改进任务列表（可执行） | 对应 Agent |
| **执行改进** | 改进任务列表 | 修改后的文档 | 对应 Agent |
| **复评验证** | 修改后的文档 | 复评报告 | chip-doc-scorer |
| **达标确认** | 复评报告 | 确认/继续改进 | 用户或 chip-arch-reviewer |

### 1.3 达标标准

| 文档类型 | 总分达标线 | 单维度达标线 | 无 Critical 扣分项 |
|----------|-----------|-------------|-------------------|
| FS | ≥ 80 分 | 每维度 ≥ 60% | 必须 |
| UA | ≥ 85 分 | 每维度 ≥ 65% | 必须 |
| RTL | ≥ 85 分 | 每维度 ≥ 65% | 必须 |

## 2. 评分维度与改进映射

### 2.1 FS 评分维度（8 维度）

| 维度 | 权重 | 低分时改进方向 |
|------|------|---------------|
| 需求完整性 | 15% | 补充缺失 REQ、完善 RTM |
| 接口定义 | 15% | 补充端口列表、完善时序图 |
| 功能描述 | 15% | 补充工作模式、数据流、控制流 |
| PPA 规格 | 10% | 量化 PPA 指标、补充计算依据 |
| 寄存器定义 | 10% | 补充寄存器位域、地址映射 |
| 异常处理 | 10% | 补充异常场景、超时处理 |
| 时钟复位 | 10% | 明确时钟域、复位策略 |
| 文档规范 | 15% | 修复格式、补充图表、完善追溯 |

### 2.2 UA 评分维度（10 维度）

| 维度 | 权重 | 低分时改进方向 |
|------|------|---------------|
| 数据通路完整性 | 12% | 补充信号链、消除断点 |
| 控制逻辑完整性 | 10% | 补充控制信号、流控机制 |
| 状态机设计 | 10% | 补充状态转移、非法状态回收 |
| 接口一致性 | 12% | 对齐 FS 端口、修正位宽 |
| 时序分析 | 10% | 补充关键路径、Tslack 计算 |
| PPA 预估 | 8% | 量化预估、补充计算依据 |
| FIFO/缓冲设计 | 8% | 补充深度计算依据 |
| IP/CBB 集成 | 8% | 补充实例化参数、适配逻辑 |
| 图表完整性 | 12% | 补充缺失图表、修复图文不一致 |
| 文档规范 | 10% | 修复格式、补充追溯 |

### 2.3 RTL 评分维度（10 维度）

| 维度 | 权重 | 低分时改进方向 |
|------|------|---------------|
| 功能正确性 | 15% | 修复 Lint 错误、消除功能缺陷 |
| 编码规范 | 12% | 修复 Verible 违规、统一命名 |
| 状态机实现 | 10% | 补充 default 分支、非法状态回收 |
| 数据通路实现 | 10% | 消除位宽不匹配、补充信号链 |
| CDC 实现 | 10% | 补充同步器、修复 CDC 违规 |
| SVA 覆盖 | 10% | 补充缺失断言、提升覆盖率 |
| 代码可读性 | 8% | 改善命名、补充注释 |
| 参数化 | 8% | 提取硬编码为参数 |
| 综合结果 | 7% | 优化面积/时序 |
| 文档追溯 | 10% | 补充架构章节引用 |

## 3. 改进优先级排序

### 3.1 优先级规则

| 优先级 | 条件 | 处理方式 |
|--------|------|----------|
| **P0 紧急** | Critical 扣分项 | 立即修复，阻塞后续 |
| **P1 高** | 权重 ≥ 12% 且得分率 < 60% | 优先修复 |
| **P2 中** | 权重 ≥ 10% 且得分率 < 70% | 计划修复 |
| **P3 低** | 其他扣分项 | 有空修复 |

### 3.2 改进项格式

```markdown
| 改进项 ID | 维度 | 当前得分 | 目标得分 | 优先级 | 改进措施 | 负责 Agent |
|-----------|------|----------|----------|--------|----------|-----------|
| IMP-001 | 数据通路完整性 | 6/12 | 10/12 | P1 | 补充 stage3→stage4 信号链 | chip-microarch-writer |
| IMP-002 | 状态机设计 | 5/10 | 9/10 | P1 | 补充 S_ERROR→S_IDLE 回收路径 | chip-microarch-writer |
```

## 4. 跨文档一致性自动修复

### 4.1 一致性检查维度

| 检查维度 | 源文档 | 目标文档 | 检查内容 |
|----------|--------|----------|----------|
| 端口一致性 | FS §6.2 | UA §4.1 | 信号名、位宽、方向 |
| 端口一致性 | UA §4.1 | RTL module | 信号名、位宽、方向 |
| 参数一致性 | FS §8 | UA §9 | PPA 参数值 |
| 参数一致性 | UA §9 | RTL parameter | 参数名、值 |
| FSM 一致性 | UA §5.3 | RTL FSM | 状态名、编码、转移条件 |
| FIFO 一致性 | UA §5.5 | RTL FIFO | 位宽、深度 |
| 寄存器一致性 | FS §7 | RTL reg | 地址、位域 |

### 4.2 不一致修复建议

| 不一致类型 | 修复原则 | 修复建议格式 |
|-----------|----------|-------------|
| **位宽不匹配** | 以 FS 为准（FS 是 single source） | `建议：将 UA/RTL 的 {signal} 位宽从 {old} 修改为 {new}（与 FS §6.2 一致）` |
| **信号名不一致** | 以 FS 为准 | `建议：将 UA/RTL 的 {old_name} 重命名为 {new_name}（与 FS §6.2 一致）` |
| **参数值不一致** | 以 FS 为准 | `建议：将 UA/RTL 的 {param} 值从 {old} 修改为 {new}（与 FS §8 一致）` |
| **FSM 状态缺失** | 以 UA 为准（UA 是 FSM 设计源） | `建议：在 RTL 中补充状态 {state}（与 UA §5.3 一致）` |
| **FIFO 参数不一致** | 以 UA 为准 | `建议：将 RTL 的 {fifo} 深度从 {old} 修改为 {new}（与 UA §5.5 一致）` |

### 4.3 一致性修复流程

```
跨文档一致性检查
  ├─ 发现不一致
  │  ├─ 确定 single source（FS > UA > RTL）
  │  ├─ 生成修复建议
  │  ├─ 评估修复影响（是否触发级联更新）
  │  └─ 输出修复建议清单
  └─ 全部一致
     └─ 输出"一致性检查通过"
```

## 5. 复评策略

### 5.1 复评范围

| 改进类型 | 复评范围 | 复评深度 |
|----------|----------|----------|
| P0 Critical 修复 | 仅复评修复项 | 验证修复是否有效 |
| P1 高优先级修复 | 复评修复项 + 相关维度 | 验证修复无副作用 |
| P2/P3 修复 | 全量复评 | 完整评分 |

### 5.2 复评达标判定

| 条件 | 判定 |
|------|------|
| 总分达标 + 无 Critical + 单维度达标 | ✅ 达标 |
| 总分达标 + 有 Critical | ❌ 未达标（继续修复 Critical） |
| 总分未达标 + 单维度达标 | ❌ 未达标（继续改进低分维度） |
| 总分达标 + 单维度未达标 | ⚠️ 有条件达标（标注未达标维度） |

### 5.3 最大迭代次数

| 场景 | 最大迭代 | 超限处理 |
|------|----------|----------|
| 常规改进 | 3 轮 | 暂停，人工评估是否继续 |
| Critical 修复 | 5 轮 | 暂停，人工介入 |
| 一致性修复 | 2 轮 | 暂停，报告残留不一致 |

## 6. 集成规则

### 6.1 chip-arch-reviewer 集成

- 评审时调用 chip-doc-scorer 进行初始评分
- 根据评分结果生成改进清单
- 改进完成后执行复评
- 评审报告中包含评分→改进→复评闭环记录

### 6.2 chip-fs-writer 集成

- FS 编写完成后自评（参考评分维度）
- 收到评审改进清单后按优先级执行改进
- 改进完成后请求复评

### 6.3 chip-microarch-writer 集成

- UA 编写完成后自评（参考评分维度）
- 收到评审改进清单后按优先级执行改进
- 跨文档一致性问题以 FS 为准进行修复
- 改进完成后请求复评
