# 跨 Agent 一致性规范（共享）

> 本模板定义芯片 Agent 间的一致性规则，确保所有 Agent 产出物在命名、格式、概念上保持一致。
> 供所有芯片 Agent 共同引用。

---

## 1. 一致性问题分类

| 类别 | 问题类型 | 影响 | 严重级别 |
|------|----------|------|----------|
| 命名不一致 | 同一信号/模块在不同文档中命名不同 | 集成错误 | Critical |
| 接口不一致 | 端口定义/位宽在 FS/UA/RTL 中不一致 | 实现错误 | Critical |
| 参数不一致 | 参数名/默认值在不同文档中不一致 | 配置错误 | Major |
| 格式不一致 | 文档格式/表格结构不统一 | 可读性差 | Minor |
| 概念不一致 | 同一概念在不同文档中定义不同 | 理解偏差 | Major |

---

## 2. 命名一致性规则

### 2.1 信号命名一致性

**铁律：同一信号在 REQ→FS→UA→RTL→验证全链路中必须使用完全相同的命名。**

| 层级 | 命名来源 | 检查方式 |
|------|----------|----------|
| FS §6.2 信号列表 | 信号名定义源头 | 所有下游必须引用 |
| UA §4.1 端口列表 | 继承 FS 命名 | 必须与 FS 一致 |
| RTL 端口声明 | 继承 UA 命名 | 必须与 UA 一致 |
| SVA/UVM | 继承 RTL 命名 | 必须与 RTL 一致 |

**命名漂移检测**：
```bash
# 检查 FS 信号名与 RTL 端口名一致性
grep -oP '`\w+`' fs_doc.md | sort > fs_signals.txt
grep -oP 'output\s+(reg|wire)\s+\[.*?\]\s+(\w+)' rtl.v | grep -oP '\w+$' | sort > rtl_ports.txt
diff fs_signals.txt rtl_ports.txt
```

### 2.2 模块命名一致性

| 层级 | 命名规则 | 示例 |
|------|----------|------|
| FS §5 子模块名 | `{module}_{submodule}` | `data_adpt_input_if_mod` |
| UA 文档标题 | 与 FS 一致 | `data_adpt_input_if_mod` |
| RTL 模块名 | 与 FS 一致 | `module data_adpt_input_if_mod` |
| 文件名 | 与模块名一致 | `data_adpt_input_if_mod.v` |
| UVM 组件名 | `{module}_{submodule}_{type}` | `data_adpt_input_if_driver` |

### 2.3 参数命名一致性

| 层级 | 命名规则 | 示例 |
|------|----------|------|
| FS §8 PPA | `{PARAM_NAME}` | `DATA_WIDTH` |
| UA §4.1 端口 | 与 FS 一致 | `DATA_WIDTH` |
| RTL parameter | 与 FS 一致 | `parameter DATA_WIDTH = 32` |
| UVM config | 与 RTL 一致 | `uvm_config_db#(int)::set(null, "*", "DATA_WIDTH", 32)` |

## 3. 接口一致性规则

### 3.1 端口定义一致性

**铁律：FS §6.2 信号列表是端口定义的唯一真相源。**

| 检查项 | FS 定义 | UA 定义 | RTL 实现 | 判定 |
|--------|---------|---------|----------|------|
| 信号名 | `src_data` | `src_data` | `src_data` | ✅ 一致 |
| 方向 | Input | Input | `input wire` | ✅ 一致 |
| 位宽 | `[DATA_WIDTH-1:0]` | `[DATA_WIDTH-1:0]` | `[DATA_WIDTH-1:0]` | ✅ 一致 |
| 时钟域 | clk | clk | clk | ✅ 一致 |
| 复位值 | 0 | 0 | `if (!rst_n) data_r <= 0` | ✅ 一致 |

**不一致处理**：
- FS 与 UA 不一致 → 以 FS 为准，修正 UA
- UA 与 RTL 不一致 → 以 UA 为准，修正 RTL
- FS 需求变更 → 按变更传播规则级联更新

### 3.2 接口协议一致性

| 检查项 | FS 定义 | UA 时序 | RTL 实现 | 判定 |
|--------|---------|---------|----------|------|
| 握手协议 | Valid-Ready | 时序图一致 | 实现一致 | ✅ |
| 握手时序 | valid 不依赖 ready | 时序图标注 | `valid_r <= next_valid` | ✅ |
| 超时阈值 | 1024 cycles | UA §5.2 | `timeout_cnt >= 1024` | ✅ |

## 4. 概念一致性规则

### 4.1 统一术语表

| 术语 | 定义 | 禁止替代 |
|------|------|----------|
| 有效数据 | `valid && ready` 握手成功的数据 | "有效"、"数据有效" |
| 背压 | 下游 `ready` 拉低反压上游 | "反压"、"阻塞" |
| 信用 | credit 计数流控机制 | "额度"、"配额" |
| 突发 | burst 传输 | "连续传输"、"批量传输" |
| 事务 | transaction 完整传输单元 | "传输"、"操作" |
| 包 | packet 网络层数据单元 | "数据包"、"报文" |
| 帧 | frame 链路层数据单元 | "数据帧" |

### 4.2 概念定义引用

当使用跨模块概念时，必须引用定义来源：

```markdown
<!-- 概念引用：信用流控机制定义见 FS §4.4 -->
<!-- 概念引用：背压传播规则见 UA §5.2 -->
```

## 5. 格式一致性规则

### 5.1 文档格式

| 元素 | 格式规则 | 示例 |
|------|----------|------|
| 端口列表表头 | `# / 信号名 / 方向 / 位宽 / 类型 / 时钟域 / 复位值 / 功能描述` | 统一 8 列 |
| 状态转移表 | `当前状态 / 转移条件 / 次态 / 输出动作` | 统一 4 列 |
| 时序参数表 | `参数 / 值 / 单位 / 说明` | 统一 4 列 |
| PPA 表 | `指标 / 数值 / 单位 / 约束类型 / 条件` | 统一 5 列 |

### 5.2 代码格式

| 元素 | 格式规则 | 来源 |
|------|----------|------|
| 缩进 | 4 空格 | coding-style.md §12 |
| 命名 | 小写下划线 | coding-style.md §2 |
| 注释 | `//` 单行，`/* */` 多行 | coding-style.md §12 |
| 文件头 | Module/Function/Author/Date/Revision | coding-style.md §1 |

## 6. 一致性检查流程

### 6.1 自动检查

| 检查项 | 检查方式 | 触发时机 |
|--------|----------|----------|
| 信号名一致性 | 脚本对比 FS/UA/RTL 信号名 | 每次 Agent 产出后 |
| 参数一致性 | 脚本对比参数定义 | 每次 Agent 产出后 |
| 端口位宽一致性 | 脚本对比端口声明 | 每次 Agent 产出后 |

### 6.2 人工检查

| 检查项 | 检查方式 | 触发时机 |
|--------|----------|----------|
| 概念一致性 | 评审文档中的术语使用 | 评审阶段 |
| 格式一致性 | 检查文档格式是否统一 | 评审阶段 |
| 接口协议一致性 | 对比时序图与 RTL 实现 | 评审阶段 |

---

## 7. 不一致处理流程

```
发现不一致 → 判定真相源 → 修正下游 → 验证一致性 → 记录偏差
```

| 步骤 | 操作 | 负责 Agent |
|------|------|-----------|
| 1. 发现不一致 | 检查或评审中发现 | 任意 Agent |
| 2. 判定真相源 | FS > UA > RTL（上游优先） | `chip-arch-reviewer` |
| 3. 修正下游 | 按真相源修正下游文档/代码 | 对应 Agent |
| 4. 验证一致性 | 重新检查一致性 | `chip-arch-reviewer` |
| 5. 记录偏差 | 如有合理偏差，记录 `[PLAN-DEVIATION]` | 对应 Agent |

| Agent | 一致性职责 |

| `chip-fs-writer` | 定义信号/模块/参数命名（真相源） |

| `chip-code-writer` | 继承 UA 命名，标注引用 |
| `chip-verfi-arch` | 验证术语与 FS 一致 |
| `chip-env-writer` | UVM 命名与 RTL 一致 |
| `chip-arch-reviewer` | 一致性检查、偏差确认 |
| `chip-project-lead` | 一致性问题协调 |
