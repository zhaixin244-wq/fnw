# 知识管理方法论

> 定义项目经验沉淀、Agent 错误模式学习和跨会话知识传递的规范化流程。

---

## 1. 知识分类体系

### 1.1 知识层级

| 层级 | 说明 | 存储位置 | 生命周期 |
|------|------|----------|----------|
| **协议/标准知识** | PCIe/AXI/NVMe 等协议规范 | Wiki (`tools/claude-obsidian/wiki/`) | 长期 |
| **CBB/IP 知识** | 可复用组件的接口和约束 | Wiki (`wiki/entities/`) | 长期 |
| **项目经验知识** | 特定项目的设计决策和教训 | `memory/project_*.md` | 中期 |
| **Agent 能力知识** | Agent 的擅长领域和常见错误 | `memory/agent_*.md` | 中期 |
| **会话上下文知识** | 当前工作状态和待办 | `tools/claude-obsidian/wiki/hot.md` | 短期 |

### 1.2 知识流转

```
原始文档 → Wiki Ingest → 结构化知识 → Agent 检索 → 应用到设计
                                                      │
项目完成 → 经验沉淀 → 记忆文件 → 下次会话加载 ←──────┘
```

---

## 2. 项目经验沉淀流程

### 2.1 沉淀时机

| 触发点 | 沉淀内容 | 目标文件 |
|--------|----------|----------|
| **项目里程碑完成** | 关键设计决策、架构选型理由 | `memory/project_{name}_decisions.md` |
| **评审完成** | 高频缺陷模式、评审经验 | `memory/project_{name}_review.md` |
| **Bug 修复完成** | 根因分析、修复方案、预防措施 | `memory/project_{name}_lessons.md` |
| **项目结束** | 项目全景总结、改进点 | `memory/project_{name}_summary.md` |

### 2.2 沉淀内容模板

```markdown
# {项目名} 经验沉淀

## 设计决策
| 决策 | 选项 | 选择 | 理由 | 效果 |
|------|------|------|------|------|
| FIFO 深度 | 8/16/32 | 16 | 突发 8 beats + 50% 裕量 | 满足需求 |

## 踩过的坑
| 问题 | 根因 | 解决方案 | 预防措施 |
|------|------|----------|----------|
| CDC 亚稳态 | 多 bit 直接跨域 | 改用异步 FIFO | CDC 检查清单增强 |

## Agent 表现
| Agent | 亮点 | 不足 | 改进建议 |
|-------|------|------|----------|
| chip-code-writer | FSM 设计准确 | FIFO 深度计算偏保守 | 调整裕量系数 |

## 可复用经验
- 经验 1: {描述}
- 经验 2: {描述}
```

### 2.3 沉淀质量标准

| 标准 | 要求 |
|------|------|
| **具体性** | 记录具体问题和方案，非泛泛而谈 |
| **可追溯** | 关联到具体 REQ/文件/代码行 |
| **可行动** | 每条教训有明确的预防措施 |
| **非冗余** | 检查是否与已有记忆重复 |

## 3. Agent 错误模式学习

### 3.1 错误模式识别

| 识别方式 | 说明 |
|----------|------|
| **评审反馈** | chip-arch-reviewer 标记的缺陷模式 |
| **返工记录** | Agent 输出被修改的频率和原因 |
| **缺陷逃逸** | 下游发现的上游 Agent 遗漏 |
| **降级触发** | Agent 降级策略被触发的场景 |

### 3.2 错误模式→改进映射

| 错误模式 | 影响 Agent | 改进方式 | 改进目标 |
|----------|-----------|----------|----------|
| 协议理解偏差 | code-writer | 增强 Wiki 检索权重 | 检索命中率提升 |
| 功能需求遗漏 | fs-writer | 增加 BDD 场景覆盖检查 | 需求覆盖率 100% |
| 接口定义不一致 | microarch-writer | 强化 FS→UA 端口映射检查 | 一致性 100% |
| CDC 处理缺失 | code-writer | 增强 CDC 检查清单 | CDC 缺陷归零 |
| FSM 设计缺陷 | code-writer | 增加 FSM 形式验证 | FSM 缺陷归零 |
| PPA 估算偏差 | microarch-writer | 增加历史数据参考 | 估算误差 ≤ 20% |

### 3.3 学习闭环

```
错误发生 → 识别模式 → 更新规则/清单 → 下次执行时应用 → 验证改进效果
    ↑                                                        │
    └────────────────────────────────────────────────────────┘
```

## 4. 跨会话知识传递

### 4.1 传递机制

| 机制 | 说明 | 适用场景 |
|------|------|----------|
| **Hot Cache** | `hot.md` 存储当前工作上下文 | 会话恢复 |
| **Memory Index** | `MEMORY.md` 存储记忆索引 | 跨会话记忆 |
| **Project Memory** | `memory/project_*.md` 存储项目知识 | 项目经验 |
| **Feedback Memory** | `memory/feedback_*.md` 存储行为纠正 | Agent 行为调整 |
| **Wiki** | 结构化知识库 | 协议/CBB 知识 |

### 4.2 知识加载优先级

新会话启动时按以下优先级加载：

| 优先级 | 加载内容 | 说明 |
|--------|----------|------|
| P0 | Hot Cache | 立即恢复工作上下文 |
| P1 | MEMORY.md 索引 | 了解记忆分布 |
| P2 | 相关项目记忆 | 根据当前任务加载相关项目经验 |
| P3 | 反馈记忆 | 加载行为纠正规则 |
| P4 | Wiki 知识 | 按需检索，不预加载 |

### 4.3 知识更新规则

| 场景 | 更新动作 |
|------|----------|
| 发现新知识 | 写入对应层级的记忆文件，更新 MEMORY.md |
| 知识过时 | 更新或删除对应记忆文件 |
| 知识冲突 | 以最新信息为准，更新记忆 |
| 重复知识 | 合并到已有记忆，不创建新文件 |

## 5. 集成规则

### 5.1 所有 Agent 通用

- Agent 激活时加载相关记忆（Hot Cache + 项目记忆 + 反馈记忆）
- Agent 执行过程中发现新知识时，评估是否需要沉淀
- Agent 完成任务后，触发项目经验沉淀（如适用）

### 5.2 chip-project-lead 专项

- 项目里程碑时主动触发经验沉淀
- 项目结束时生成项目总结记忆
- 定期审查记忆有效性，清理过时记忆
- 根据 Agent 度量数据生成改进建议记忆

### 5.3 chip-arch-reviewer 专项

- 评审完成后沉淀高频缺陷模式
- 将评审经验转化为检查规则增强
- 记录跨文档一致性问题的典型模式
