# 验证收敛规范（共享）

> 本模板定义芯片验证的收敛标准和签核条件，确保验证过程可量化、可追踪、可签核。
> 供 `chip-verfi-arch`、`chip-env-writer`、`chip-arch-reviewer` 共同引用。

---

## 1. 验证收敛模型

```
测试计划 → 测试实现 → 测试执行 → 覆盖率收集 → 缺陷修复 → 收敛判定 → 签核
```

**收敛定义**：验证覆盖率达标 + 缺陷逃逸率可控 + 回归通过率稳定 = 验证收敛。

---

## 2. 覆盖率收敛标准

### 2.1 功能覆盖率

| 覆盖类型 | 目标 | 收敛条件 | 签核要求 |
|----------|------|----------|----------|
| 代码行覆盖率 | ≥ 95% | 连续 3 轮无新增覆盖 | 必须达标 |
| 分支覆盖率 | ≥ 90% | 连续 3 轮无新增覆盖 | 必须达标 |
| FSM 状态覆盖率 | 100% | 所有状态已访问 | 必须达标 |
| FSM 转移覆盖率 | ≥ 95% | 关键转移已覆盖 | 必须达标 |
| 功能覆盖率 | ≥ 90% | 所有 coverpoint 已采样 | 必须达标 |
| 断言覆盖率 | 100% | 所有 cover property 已触发 | 必须达标 |

### 2.2 覆盖率收敛曲线

```
覆盖率
100% |                    ___________
 90% |               ____/
 80% |          ____/
 50% |     ____/
  0% |____/
     +--------------------------------→ 时间
       T1    T2    T3    T4    T5
```

**收敛判定**：
- T1→T2：快速上升期（新测试用例生效）
- T2→T4：缓慢上升期（边界场景覆盖）
- T4→T5：平台期（覆盖率稳定，无新增覆盖）
- **连续 3 轮回归覆盖率波动 < 1%** → 覆盖率收敛

### 2.3 覆盖率缺口处理

| 缺口类型 | 处理方式 | 负责 Agent |
|----------|----------|-----------|
| 未覆盖的 RTL 代码 | 分析是否为不可达代码，标注或补充测试 | `chip-verfi-arch` |
| 未覆盖的 FSM 转移 | 补充边界测试场景 | `chip-env-writer` |
| 未覆盖的功能点 | 补充 BDD 场景 + UVM Sequence | `chip-verfi-arch` + `chip-env-writer` |
| 不可覆盖项 | 记录原因，评审确认后豁免 | `chip-arch-reviewer` |

## 3. 缺陷收敛标准

### 3.1 缺陷分类

| 严重级别 | 定义 | 修复时限 | 阻塞签核 |
|----------|------|----------|----------|
| Critical | 功能完全不可用 / 数据丢失 | 立即修复 | 是 |
| Major | 功能部分异常 / 性能严重下降 | 24h 内修复 | 是 |
| Minor | 功能可用但有瑕疵 | 版本内修复 | 否 |
| Cosmetic | 界面/日志/文档问题 | 按计划修复 | 否 |

### 3.2 缺陷收敛曲线

```
新增缺陷数
    |  *
    | * *
    |*   *
    |     *  *
    |         *   *
    |              *  *  *
    +-----------------------------→ 时间
       快速发现期  收敛期  稳定期
```

**收敛判定**：
- 连续 2 周新增缺陷数 < 修复缺陷数
- Critical/Major 缺陷数 = 0
- 缺陷密度 < 0.1 个/KLOC

### 3.3 缺陷逃逸率

| 阶段 | 逃逸率目标 | 计算公式 |
|------|-----------|----------|
| 仿真→综合 | < 5% | 综合发现的仿真应覆盖缺陷 / 总缺陷 |
| 综合→后端 | < 2% | 后端发现的综合应覆盖缺陷 / 总缺陷 |
| 后端→硅后 | < 0.5% | 硅后发现的后端应覆盖缺陷 / 总缺陷 |

---

## 4. 回归测试收敛标准

### 4.1 回归通过率

| 回归类型 | 通过率目标 | 收敛条件 |
|----------|-----------|----------|
| 冒烟测试 | 100% | 每次必须 100% |
| 全量回归 | ≥ 98% | 连续 3 轮稳定 |
| 随机回归 | ≥ 95% | 连续 5 轮稳定 |
| 夜间回归 | ≥ 99% | 连续 7 天稳定 |

### 4.2 回归稳定性

**不稳定测试判定**：
- 同一测试在相同配置下连续 3 次结果不一致
- 测试结果依赖执行顺序
- 测试结果依赖随机种子

**处理方式**：
1. 隔离不稳定测试到 quarantine 列表
2. 分析根因（竞态、时序、随机约束）
3. 修复后重新加入回归
4. quarantine 列表中的测试不计入通过率

## 5. 验证签核条件

### 5.1 签核检查清单

| # | 检查项 | 标准 | 判定 |
|---|--------|------|------|
| VC-01 | 功能覆盖率 ≥ 90% | 覆盖率报告 | Must |
| VC-02 | 代码覆盖率 ≥ 95% | 覆盖率报告 | Must |
| VC-03 | FSM 状态覆盖率 100% | 覆盖率报告 | Must |
| VC-04 | Critical 缺陷 = 0 | 缺陷跟踪系统 | Must |
| VC-05 | Major 缺陷 = 0 | 缺陷跟踪系统 | Must |
| VC-06 | 回归通过率 ≥ 98% | 回归报告 | Must |
| VC-07 | 连续 3 轮覆盖率波动 < 1% | 趋势分析 | Must |
| VC-08 | 所有 BDD 场景有对应测试 | 追溯矩阵 | Should |
| VC-09 | 所有 SVA 断言已绑定 RTL | 断言报告 | Should |
| VC-10 | 不稳定测试已隔离 | quarantine 列表 | Should |

### 5.2 签核流程

```
覆盖率达标 → 缺陷清零 → 回归稳定 → 签核检查清单 → 评审确认 → 签核
```

**签核角色**：
- `chip-verfi-arch`：验证架构完整性确认
- `chip-env-writer`：验证环境质量确认
- `chip-arch-reviewer`：最终签核确认
- `chip-project-lead`：签核审批

---

## 6. 各 Agent 验证收敛职责

| Agent | 职责 | 输出物 |
|-------|------|--------|
| `chip-verfi-arch` | 验证计划完整性、覆盖率目标定义 | 验证计划、覆盖率模型 |
| `chip-env-writer` | 验证环境质量、测试用例实现 | UVM 环境、测试用例 |
| `chip-arch-reviewer` | 签核检查、收敛判定 | 签核报告 |
| `chip-project-lead` | 签核审批、进度跟踪 | 验证状态报告 |
