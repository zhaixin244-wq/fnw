# chip-requirement-arch 流程质量评分标准

> 评估芯片需求探索 & 方案论证 Agent（苏启辰/Sean）的流程执行质量。
> 满分 100 分，按维度加权评分。
> 版本：v12.0（同步 agent v12.0 — D 阶段上下文隔离 + RTL 就绪度检查 + 自包含 todolist + stageD group/step 统一编码 + 调试模式 + 路径统一 + REQ 编号全局唯一 + stageD 执行顺序统一 + Wiki 头脑风暴集成 + 专项 Agent 编排）

---

## ⚠️ 评估铁律（必须严格遵循）

> **以下铁律优先于一切评分规则。违反铁律的评估报告视为无效。**

1. **门控检查必须第一步执行**：先检查 G-01~G-09，任一 FAIL → 直接 D 级，**禁止继续评分**
2. **门控检查必须第二步执行**：检查 G-10~G-18，任一 FAIL → 直接 C 级，**禁止继续评分**
3. **目录结构必须用命令验证**：使用 `find`/`ls` 命令实际检查文件系统，**禁止仅凭文档内容推断**
4. **文档质量必须检查实际内容**：读取文件内容验证章节完整性、REQ 连续性、格式规范性，**禁止仅凭文件存在给分**
5. **评估结果必须可复现**：同一输入必须产生相同评分，**禁止主观调整分数**
6. **门控违规必须输出清单**：evaluation.md §0 必须列出所有门控检查结果，**禁止跳过 §0**
7. **stageD 编码必须符合统一规则**：验证 stageD 使用 `group{N}-step{M}` 格式，禁止使用旧 D0-D14 编码

### 主观性维度说明

D1（需求采集完整性）的部分子项依赖评估人对 PR 文件内容的主观判断（如"探索深度是否足够"、"灰色表达是否正确处理"）。为保证评估一致性：

1. **双人校验**：关键项目建议两人独立评估，取均值
2. **证据引用**：每个主观打分必须引用 PR 文件中的具体文字作为依据
3. **偏差容限**：D1 维度允许 ±1 分的评估偏差

## 评分流程（严格按顺序执行）

```
步骤 1：门控检查（G-01~G-09）— 必须第一步
  ├─ 任一 FAIL → 直接 D 级，输出违规清单，评分结束
  └─ 全部 PASS → 继续步骤 2

步骤 2：门控检查（G-10~G-18）— 必须第二步
  ├─ 任一 FAIL → 直接 C 级，输出违规清单，评分结束
  └─ 全部 PASS → 继续步骤 3

步骤 3：目录结构验证 — 必须第三步
  ├─ 使用 find/ls 命令检查实际文件系统
  ├─ 验证子模块一级目录、孙模块子目录、文件数量
  └─ 记录到 §0 门控检查结果

步骤 4：文档质量验证 — 必须第四步
  ├─ 读取每个文件的实际内容
  ├─ 检查章节完整性、REQ 连续性、格式规范性
  └─ 记录到 §0 门控检查结果

步骤 5：逐维度打分（D1~D10）— 门控全部 PASS 后
  ├─ 每个子项独立打分，满分见各子项标题
  └─ 维度得分 = 子项分数之和

步骤 6：加权总分计算
  └─ 总分 = Σ(维度得分 / 维度满分 × 维度权重)

步骤 7：等级判定
  ├─ 门控 1 触发 → D 级
  ├─ 门控 2 触发 → C 级
  ├─ 总分 ≥90 → S 级
  ├─ 总分 ≥80 → A 级
  ├─ 总分 ≥70 → B 级
  ├─ 总分 ≥60 → C 级
  └─ 总分 <60 → D 级

步骤 8：输出 evaluation.md
  ├─ §0：门控检查结果（必须首先输出）
  ├─ §1~§10：各维度评分详情
  ├─ §11：加权总分与等级
  └─ §12：扣分项清单与优化建议
```

### 门控 1 验证脚本

```bash
#!/bin/bash
# gate_check_1.sh - 流程完整性门控检查
MODULE=$1
ROOT="<module>_work/ds/doc/pr"
PASS=true

# G-01: stageB phase1 完成率
B_COUNT=$(grep -c "✅" "${ROOT}/${MODULE}_requirement_summary_v1.0.md" 2>/dev/null || echo 0)
[ "$B_COUNT" -lt 20 ] && echo "G-01 FAIL: stageB phase1 确认项 ${B_COUNT} < 20" && PASS=false

# G-02: stageB phase2 执行
grep -q "stageB phase2\|Feature Discovery\|头脑风暴" "${ROOT}/${MODULE}_requirement_summary_v1.0.md" 2>/dev/null || { echo "G-02 FAIL: stageB phase2 未执行"; PASS=false; }

# G-03: stageC phase1 执行
grep -q "stageC phase1\|矛盾检测" "${ROOT}/${MODULE}_pr_v1.0.md" 2>/dev/null || { echo "G-03 FAIL: stageC phase1 未执行"; PASS=false; }

# G-04: stageC phase2 执行
[ ! -f "${ROOT}/${MODULE}_requirement_summary_v1.0.md" ] && echo "G-04 FAIL: 需求汇总表不存在" && PASS=false

# G-05: stageD 执行
[ ! -f "${ROOT}/${MODULE}_solution_v1.0.md" ] && echo "G-05 FAIL: 方案文档不存在" && PASS=false

# G-06: E 阶段 todolist（支持每个子模块独立 todolist）
TODOLIST_COUNT=$(find "${ROOT}" -name "todolist.md" -type f 2>/dev/null | wc -l)
[ "$TODOLIST_COUNT" -lt 1 ] && echo "G-06 FAIL: 未发现任何 todolist 文件" && PASS=false

# G-07: 子模块目录
SUB_DIRS=$(find "${ROOT}" -mindepth 2 -maxdepth 2 -type d 2>/dev/null | wc -l)
[ "$SUB_DIRS" -lt 1 ] && echo "G-07 FAIL: 无子模块目录" && PASS=false

# G-08: 子模块交付文件
for d in $(find "${ROOT}" -mindepth 2 -maxdepth 2 -type d 2>/dev/null); do
  FC=$(find "$d" -type f 2>/dev/null | wc -l)
  [ "$FC" -lt 5 ] && echo "G-08 FAIL: ${d} 文件数 ${FC} < 5" && PASS=false
done

# G-08b: 目录结构统一性
GRANDCHILD_IN_ROOT=0
for d in $(find "${ROOT}" -mindepth 2 -maxdepth 2 -type d 2>/dev/null); do
  SUB_SUB=$(find "$d" -mindepth 1 -maxdepth 1 -type d 2>/dev/null | wc -l)
  if [ "$SUB_SUB" -gt 0 ]; then
    for sd in $(find "$d" -mindepth 1 -maxdepth 1 -type d 2>/dev/null); do
      HAS_OUTPUTS=$(find "$sd" -maxdepth 1 -type d -name "outputs" 2>/dev/null | wc -l)
      HAS_FLOW=$(find "$sd" -maxdepth 1 -type d -name "flow" 2>/dev/null | wc -l)
      if [ "$HAS_OUTPUTS" -eq 0 ] && [ "$HAS_FLOW" -eq 0 ]; then
        echo "G-08b WARN: ${sd} 缺少 outputs/ 或 flow/ 子目录"
      fi
    done
  fi
done

# G-09: F 阶段执行
grep -q "§14\|顶层集成\|接口一致性" "${ROOT}/${MODULE}_solution_v1.0.md" 2>/dev/null || { echo "G-09 FAIL: F 阶段未执行"; PASS=false; }

$PASS && echo "门控 1: 全部 PASS" || echo "门控 1: 存在 FAIL → D 级"
```

## 门控 3：目录结构一致性门控（v3.0 新增）

> **铁律：E 阶段触发时，必须验证目录结构符合统一规则。不符合 → 在 D5.5 扣分。**

| # | 检查项 | 验证命令 | 标准 |
|---|--------|----------|------|
| G-19 | 子模块一级目录 | `find <root> -mindepth 2 -maxdepth 2 -type d` | 子模块在 `<root>/` 下创建一级目录 |
| G-20 | 孙模块子目录 | `find <root> -mindepth 3 -maxdepth 3 -type d` | 孙模块在 `<root>/<submodule>/` 下创建子目录 |
| G-21 | 文件命名规范 | `find <submodule_dir> -type f -name "*.md" -o -name "*.yaml"` | 文件名 = `{目录名}_{类型}.md/yaml` |
| G-22 | 每个叶子节点 5 文件 | `find <leaf_dir> -type f \| wc -l` | = 5 |

### 目录结构验证脚本

```bash
#!/bin/bash
# dir_structure_check.sh - 目录结构一致性检查
ROOT=$1
echo "=== 目录结构验证 ==="

echo "一级目录（子模块）："
find "${ROOT}" -mindepth 2 -maxdepth 2 -type d | sort

echo "二级目录（孙模块）："
find "${ROOT}" -mindepth 3 -maxdepth 3 -type d | sort

echo "文件命名检查："
for d in $(find "${ROOT}" -mindepth 2 -type d); do
  DIR_NAME=$(basename "$d")
  for f in $(find "$d" -maxdepth 1 -type f -name "*.md" -o -name "*.yaml"); do
    F_NAME=$(basename "$f")
    if [[ "$F_NAME" != ${DIR_NAME}_* ]]; then
      echo "  WARN: ${f} 文件名不符合 {目录名}_{类型} 规则"
    fi
  done
done

echo "叶子节点文件数检查："
for d in $(find "${ROOT}" -mindepth 2 -type d); do
  FC=$(find "$d" -maxdepth 1 -type f 2>/dev/null | wc -l)
  SUB_DIRS=$(find "$d" -mindepth 1 -maxdepth 1 -type d 2>/dev/null | wc -l)
  if [ "$SUB_DIRS" -eq 0 ] && [ "$FC" -lt 5 ]; then
    echo "  WARN: ${d} 叶子节点文件数 ${FC} < 5"
  fi
done
```
